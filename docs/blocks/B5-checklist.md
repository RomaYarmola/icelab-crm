# B5. Чек-лист ручної перевірки

Для кроку 6.3 з [плану блока](B5-orders.md). Тестові користувачі (по одному на роль) є на `icelab-dev`, паролі лежать у файлі `.dev-users.local` у корені проєкту (у репозиторій не потрапляє). Адреса: `https://icelab-crm.vercel.app` (Production) або прев'ю PR.

Відмічайте `[x]`, що пройшло. Якщо щось не так, напишіть, на якому кроці і що побачили.

## 0. Підготовка

- Потрібні демо-клієнти «Тест: …» (вони вже є в `icelab-dev`).
- Демо-замовлення: `npm run orders:seed-dev` додає 18 замовлень у різних статусах на різні дні (в тому числі навмисний дубль, замовлення з платною доставкою і скасоване). `npm run orders:seed-dev -- --remove` видаляє їх. База одна з Production, тому запуск лише після вашого «так».
- Прайс: власник вносить ціни в «Ще → Прайс» (для 3 мм, 16 мм і 19 мм), інакше система не знає, яку ціну підставити, і її доведеться вводити вручну.

- [ ] Власник увійшов і бачить у «Замовленнях» демо-замовлення (діапазон «Інший період»: останні 7 днів і 2 наступні)

## 1. Список

- [ ] «Замовлення»: зверху «Нове замовлення», пошук, плашки «Вчора», «Сьогодні», «Завтра», «Тиждень», «Інший період», «Фільтри»
- [ ] За замовчуванням показано сьогодні. Плашка «Тиждень» показує поточний тиждень з понеділка по неділю
- [ ] «Інший період»: вкажіть дві дати, список звужується; адреса сторінки містить дати (її можна надіслати, «Назад» повертає до попереднього стану)
- [ ] Пошук за номером замовлення («№ 3472» чи «3472»), за кодом клієнта, назвою, частиною телефону
- [ ] Фільтри: статус, менеджер клієнта, спосіб доставки; кількість увімкнених видно в «Фільтри · 2»
- [ ] У рядку: клієнт і код, номер, «30 кг, виготовити 33 кг», сума, спосіб доставки, статус словом
- [ ] «Нічого не знайдено» з підказкою, коли нічого немає
- [ ] Вибір локації в шапці («Київ», «Львів») звужує список

## 2. Нове замовлення

- [ ] «Нове замовлення»: клієнт, дата виконання (сьогодні), локація (та, що вибрана в шапці)
- [ ] Пошук клієнта: «вогн», «АА15», частина телефону. Результати кнопками, клікнув і клієнт вибраний. «Змінити» повертає до пошуку
- [ ] «Створити нового клієнта» відкривається в новій вкладці, форма замовлення не губить введене
- [ ] Після вибору клієнта з'являються: адреси клієнта (адреса за замовчуванням уже вибрана), «Як минулого разу» (якщо в клієнта вже були замовлення)
- [ ] Виберіть тип льоду: під полем ціни «Ціна 75 ₴/кг (за прайсом)» чи «(ціна клієнта)». Якщо ціни немає ніде, є пояснення
- [ ] Введіть кг: «Виготовити» підставляється само. Для Нової Пошти +10% («продано 30 кг + надбавка 10%»), самовивіз без надбавки. Виправте число руками: з'являється «Виправлено вручну»
- [ ] Ціну можна вказати свою: порожнє поле означає «за прайсом»
- [ ] Вікно «Схоже замовлення вже є»: створіть замовлення тому самому клієнту на ту саму дату й тип льоду. Збереження не блокується
- [ ] «Як минулого разу»: поля заповнились з останнього замовлення клієнта, дата нова, ціни за прайсом, у додаткових позиціях ціни треба вказати
- [ ] «Додаткові позиції»: додайте «Доставку» чи «Продаж боксу», сума замовлення внизу оновлюється
- [ ] Телефон отримувача вводиться як звичайно (`050 123 45 67`)
- [ ] «Створити замовлення»: відкривається картка з повідомленням «Замовлення створено як чернетку», номер наскрізний
- [ ] Без вибраного клієнта кнопка «Створити» недоступна з підказкою «Спершу виберіть клієнта»
- [ ] Поганий ввід (від'ємні кг, неіснуюча дата) дає зрозуміле повідомлення, введене не зникає

## 3. Картка замовлення і статуси

- [ ] Вгорі номер, статус словом, клієнт (посилання на картку клієнта), дата
- [ ] «Що далі»: у чернетці «Підтвердити замовлення» і «Скасувати замовлення»
- [ ] Підтвердіть: статус «Підтверджено», під позиціями «Ціну зафіксовано при підтвердженні», в історії запис з автором і часом
- [ ] Без ціни (її немає ні в прайсі, ні в замовленні) підтвердити не вдається, є зрозуміле повідомлення
- [ ] «Скасувати замовлення» розкриває поле причини; без причини не скасовується; з причиною замовлення скасоване, причина на картці
- [ ] «Повернути на крок назад» (лише власник) теж просить причину; з підтвердженого в чернетку знімає зафіксовану ціну
- [ ] Старший локації: «Передати у виробництво» і «Позначити запакованим» для замовлень своєї локації
- [ ] «Позначити оплаченим» (власник) просить примітку, і замовлення одразу стає «Закрито» (в історії «Закрито автоматично»)
- [ ] Чернетку можна видалити (власник і менеджер): «Видалити чернетку» двома натисненнями; підтверджене лише скасовується

## 4. Зміна замовлення

- [ ] «Змінити замовлення» на картці: ті самі поля з поточними значеннями
- [ ] Змініть кг у чернетці: «Виготовити» перераховується, позиція «Лід» і сума теж
- [ ] Якщо «Виготовити» виправлено вручну, воно не перераховується при зміні кг
- [ ] У підтвердженому ціна не змінюється через форму (підказка про «Змінити ціну»), решта полів змінюється
- [ ] У виробництві й запакованому: менеджеру поля вимкнені, власнику доступне поле «Причина зміни» (обов'язкове)
- [ ] Після відправлення, у закритому й скасованому форма не відкривається (повертає на картку)
- [ ] «Керувати позиціями» на картці: додати, змінити, прибрати доплату чи бокс; позицію «Лід» тут немає

## 5. Ціна підтвердженого замовлення (власник)

- [ ] «Змінити ціну»: нова ціна й причина (обов'язкова). Після збереження: ціна й сума оновлені, на картці рядок «Ціну змінено: 75 ₴/кг → 70 ₴/кг» з причиною й автором
- [ ] Зміна прайсу (в «Ще → Прайс») не міняє вже підтверджене замовлення, а нове бере нову ціну
- [ ] Менеджер не бачить «Змінити ціну»

## 6. Права за ролями

| Роль | Список і картка | Гроші | Нове замовлення і зміна | Підтвердити, скасувати | Змінити ціну |
|---|---|---|---|---|---|
| Власник | так | так | так | так | так, з причиною |
| Менеджер | так | так | так (до виробництва) | так | ні |
| Старший локації | лише своєї локації | ні | лише «виготовити» і коментар | ні (у виробництво, запаковано, відправлено так) | ні |
| Виробництво | розділу немає | розділу немає | ні | ні | ні |
| Бухгалтер | так | так | ні | ні | ні |

- [ ] Власник
- [ ] Менеджер
- [ ] Старший локації: у списку лише замовлення його локації, без цін і сум, на картці немає внутрішнього коментаря, чуже замовлення за прямою адресою дає «сторінку не знайдено»
- [ ] Виробництво: адреса `/orders` перекидає на «Виробництво»
- [ ] Бухгалтер: бачить суми, кнопок і форм немає

## 7. Вигляд

- [ ] На телефоні 360–430 px немає горизонтальної прокрутки, шрифт не дрібніший за 16 px, кнопки й поля зручно натискати
- [ ] Форма замовлення на телефоні: екранна клавіатура не закриває поле й кнопку «Створити» (екран прокручується), для кг і ціни відкривається цифрова клавіатура, для телефону цифрова з «+»
- [ ] На екрані від 1024 px список у дві колонки, форма й картка не розтягнуті на весь екран
- [ ] Каталог `/ui-kit` (на локальному сервері) показує екрани: `?screen=order-list`, `order&status=…`, `new-order`, `edit-order&status=…`

## 8. Після перевірки

- [ ] Демо-замовлення можна лишити для блока B6 (екран виробництва) або видалити: `npm run orders:seed-dev -- --remove`
