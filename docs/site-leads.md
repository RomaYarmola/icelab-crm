# Заявки з сайту в CRM (для зміни коду сайту)

Цей документ для того, хто змінює код сайту icelab.com.ua (репозиторій `icelab-prod`, файл `src/app/api/sendMessageTelegram/route.js`). CRM лише приймає заявки, код сайту в цьому репозиторії не міняється.

## Що робить сайт

Після успішної відправки в Telegram сайт додатково надсилає заявку в CRM. Помилку CRM сайт лише записує в журнал і форму не ламає (так само, як для Google Sheets).

```
POST https://<адреса CRM>/api/leads/site
Content-Type: application/json
X-Lead-Secret: <спільний секрет>
```

Адреса CRM поки `https://icelab-crm.vercel.app`, зміниться разом з постійним доменом. Секрет `LEAD_SITE_SECRET` задається у Vercel застосунку CRM, той самий рядок кладемо у змінні середовища сайту. У код і в репозиторій секрет не записуємо.

## Тіло запиту

```json
{
  "lead": {
    "type": "замовлення",
    "name": "Коваль Олена",
    "phone": "050 123 45 67",
    "messenger": "Viber",
    "delivery": "Самовивіз зі складу у Львові",
    "comment": "Подзвоніть заздалегідь",
    "items": [
      { "title": "Гранули 16 мм", "quantity": 40, "unit": "кг", "price": 75 }
    ]
  },
  "message": "Текст повідомлення, яке пішло в Telegram",
  "receivedAt": "2026-11-17T09:00:00Z"
}
```

- `lead.phone` обов'язковий. Формат довільний (`050 123 45 67`, `+380501234567`), CRM приводить до `+380…`.
- Решта полів необов'язкові. Додаткові поля CRM ігнорує, тож сайт може надсилати, що має.
- `lead.delivery` це текст способу отримання. За ним CRM визначає локацію (слово «Львів» дає Львів, інакше Київ) і спосіб доставки («самовивіз», «Нова Пошта», «доставка», «автобус»).
- `items`: рядок із «2 мм», «3 мм», «16 мм», «19 мм» чи «блок» і кількістю в кілограмах стає льодом у чернетці, решта позицій іде в коментар чернетки.
- `receivedAt` необов'язкове (за замовчуванням момент прийому).

## Відповіді CRM

| Код | Коли | Тіло |
|---|---|---|
| 200 | Заявку прийнято | `{"draftId": "…", "duplicate": false}` |
| 200 | Така сама заявка (той самий телефон у межах 10 хвилин) уже є | `{"draftId": "…", "duplicate": true}` |
| 400 | Тіло не JSON чи немає `lead.phone` | `{"error": "…"}` |
| 401 | Немає чи неправильний `X-Lead-Secret` | `{"error": "Немає доступу."}` |
| 422 | Телефон не розпізнано | `{"error": "…"}` |
| 5xx | Збій CRM | `{"error": "…"}` |

## Що відбувається в CRM

Заявка записується, і створюється **чернетка замовлення** з джерелом «Сайт». Клієнта шукаємо за телефоном серед контактів: якщо він один, чернетка йде на нього. Якщо клієнта немає чи їх кілька, чернетка отримує «Новий клієнт», а менеджер обирає справжнього на вкладці «Замовлення, Чернетки». Нових клієнтів CRM автоматично не створює. Підтверджує чернетку менеджер, тоді вона з'являється на екрані цеху.

## Як перевірити

```bash
curl -X POST https://icelab-crm.vercel.app/api/leads/site \
  -H "Content-Type: application/json" \
  -H "X-Lead-Secret: <секрет>" \
  -d '{"lead":{"phone":"050 123 45 67","name":"Тест","delivery":"Самовивіз","items":[{"title":"Гранули 16 мм","quantity":10,"unit":"кг"}]}}'
```

Відповідь `200` із `draftId`, а чернетка видна в CRM на вкладці «Чернетки».
