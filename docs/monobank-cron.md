# Розклад monobank на бойовій базі (Supabase Cron)

Для B13 потрібен один розклад: виписка рахунку ФОП кожні 15 хвилин (ТЗ 8.7). Список рахунків застосунок оновлює сам раз на добу, окремого розкладу для нього немає. Вмикаємо розклад **лише на бойовій базі** (D29). На `icelab-dev` виписку забираємо кнопкою «Перевірити з'єднання» на екрані «Інтеграції».

## Що потрібно

1. Змінна `MONOPAY_API_KEY` у Vercel (токен monobank зі «Для розробників», позначити як sensitive).
2. Змінна `CRON_SECRET` у Vercel і той самий секрет у Supabase Vault під назвою `cron_secret` (вже налаштовано для Нової Пошти, див. [np-cron.md](np-cron.md)).
3. Адреса застосунку, наприклад `https://icelab-crm.vercel.app`.

## Як увімкнути (SQL Editor у Supabase)

```sql
select cron.schedule(
  'monobank-statement',
  '*/15 * * * *',
  $$
  select net.http_post(
    url := 'https://icelab-crm.vercel.app/api/cron/monobank',
    headers := jsonb_build_object(
      'x-cron-secret', (select decrypted_secret from vault.decrypted_secrets where name = 'cron_secret')
    ),
    timeout_milliseconds := 30000
  );
  $$
);
```

Вимкнути: `select cron.unschedule('monobank-statement');`.

## Що робить виклик

1. Раз на добу бере список рахунків токена й зберігає **лише рахунок ФОП у гривні** (особисті картки ігноруємо).
2. Просить виписку від «до чого дійшли мінус 2 дні» (перекриття для надійності), вікном не більше 31 дня. Якщо рахунок підключили вперше, за один виклик забираємо до 31 дня; якщо ще не наздогнали, наступні виклики дойдуть до сьогодні.
3. Зберігає лише надходження в гривні; дублі відсікає унікальний індекс за `id` операції.
4. Не частіше одного запиту на 60 секунд на рахунок (ліміт банку).
5. Якщо банк відповів 403, власнику в Telegram приходить «Токен monobank не працює» (один раз, доки синхронізація не вдасться).
