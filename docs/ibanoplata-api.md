# API IBAN oplata (посилання на оплату)

Для D239 (блок B13). Роман на тарифі «Преміум» (26.11.2026).

| Що | Де |
|---|---|
| Адреса API | `https://api.ibanoplata.com` |
| Документація Swagger | <https://api.ibanoplata.com/swagger> |
| Опис API у JSON | <https://api.ibanoplata.com/swagger/v2/swagger.json> |
| Ключ | заголовок `X-Api-Key`; значення лише у змінній `IBANOPLATA_API_KEY` (`.env.local` і Vercel) |

Нижче стислий опис за документацією, прочитаною **26.11.2026** (OpenAPI 3.1.1, «IbanOplata API V2», версія 2.0). **Із ключем жодного виклику ще не робили.** Перед змінами в коді звіряйтесь зі Swagger.

## Методи

| Метод | Для чого | Чи потрібен нам |
|---|---|---|
| `POST /v2/iban-invoice` | Створити посилання | так |
| `GET /v2/iban-account` | Список збережених реквізитів | для перевірки з'єднання |
| `GET /v2/iban-invoice` | Список посилань за період | можливо |
| `DELETE /v2/iban-invoice/{ibanInvoiceUid}` | Видалити посилання | поки ні |
| `GET`, `PUT /v2/iban-account/{ibanAccountUid}` | Читання й зміна реквізитів | ні, реквізити не змінюємо |
| `GET /v2/design-template` | Шаблони вигляду сторінки оплати | ні |
| `GET /ping` | Доступність сервісу | можливо |

## Створення посилання

Тіло запиту (JSON):

| Поле | Обов'язкове | Обмеження | Звідки беремо |
|---|---|---|---|
| `organizationName` | так | до 70 символів | реквізити в налаштуваннях (`payment.requisites`) |
| `identificationCode` | так | до 13 символів (ЄДРПОУ або РНОКПП) | реквізити |
| `iban` | так | до 29 символів | реквізити |
| `amount` | так | число, до двох знаків після коми, у гривнях | сума боргу відзначених замовлень |
| `paymentPurpose` | так | до 140 символів | «Оплата за замовлення №…» (D197) |
| `notes` | ні | до 512, внутрішня примітка | |
| `clientNotes` | ні | до 70, бачить платник | |
| `expirationHours` | ні | термін дії в годинах | |
| `designTemplateUid` | ні | шаблон вигляду; без нього типовий з кабінету | |

Відповідь `200`: `ibanInvoiceUid` і `ibanInvoiceUrl` (посилання для клієнта).

## Помилки

| Код | Що означає (за документацією) |
|---|---|
| `403` | Немає доступу, ключ недійсний або закінчилась передплата |
| `422` | Некоректний формат даних |

## Список посилань

`GET /v2/iban-invoice?PageNumber=1&PageSize=100&FromUtc=…` (`ToUtc` необов'язковий). `PageSize` до 100, є ознака `hasNextPage`.

## Чого в документації не знайдено

- обмежень частоти запитів;
- захисту від повторного створення того самого посилання: повторний запит, імовірно, створить нове, тому не повторюємо `POST` автоматично після обриву зв'язку.

Сповіщення про оплату (вебхук) є окремим платним доповненням сервісу; нам воно не потрібне: оплату видно у виписці monobank (D202).
