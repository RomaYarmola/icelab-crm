# Оцінка розбору заявок (B11)

Скрипт `npm run intake:eval` проганяє справжні повідомлення через Claude й показує, скільки полів розпізнано так, як ви очікували. Він нічого не записує в базу: список клієнтів лише читається. Прогін викликає справжній Claude і коштує кілька центів. Потрібен `ANTHROPIC_API_KEY` у `.env.local`.

## Як користуватись

1. Скопіюйте `intake-eval/example.json` у `intake-eval/cases.local.json` (файли `*.local.json` не потрапляють у git, бо там справжні заявки).
2. Замініть зразки на справжні повідомлення з групи (телефони копіювати не треба) і впишіть очікуваний результат.
3. Запустіть:

```bash
npm run intake:eval -- intake-eval/cases.local.json
```

Скрипт друкує, скільки зразків розпізнано повністю, точність за кожним полем і список розбіжностей.

## Формат зразка

```json
{
  "text": "ДСВ завтра 40 кг 16 мм, Нова Пошта, Львів, відділення 12",
  "location": "kyiv",
  "today": "2026-11-17",
  "expected": {
    "client_code": "АА21",
    "order_date": "2026-11-18",
    "kg_sold": 40,
    "ice_type": "16mm",
    "delivery_method": "np"
  }
}
```

- `location`: `kyiv` чи `lviv` (топік, у якому написали); типово `kyiv`.
- `today`: день повідомлення, потрібен для «завтра», «у понеділок»; типово сьогодні.
- `expected` містить лише ті поля, які ви хочете перевірити. `client_code: null` означає «клієнта в списку немає, модель не має його вгадувати».
- `ice_type`: `3mm`, `16mm` чи `19mm`. `delivery_method`: `pickup`, `our_delivery`, `np`, `bus`, `other`.

## Як читати результат

Частка збігів записується в протокол приймання, але не є критерієм приймання (ТЗ 8.3). Розбіжності допомагають зрозуміти, що поправити в підказці (`src/server/intake/prompt.ts`): скорочення назв клієнтів, жаргон, формати дат. ТЗ радить близько сотні зразків, але для першої перевірки вистачає 10–15 різних.
